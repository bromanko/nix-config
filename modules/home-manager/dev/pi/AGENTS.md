## Commit messages

When writing a commit message, follow any repository-specific
conventions. Otherwise, follow these seven rules:

1. If a body is needed, separate it from the subject with a blank line.
2. Aim to limit the subject to 50 characters; 72 is the hard limit.
3. Capitalize the first letter of the subject.
4. Do not end the subject with a period.
5. Use imperative mood in the subject ("Fix bug" or "Add feature," not
   "Fixed bug" or "Adds feature"). It must complete the sentence:
   "If applied, this commit will [subject]."
6. Wrap the body at 72 characters so it remains readable in Git tools.
7. Use the body to explain what changed and why, rather than how. Assume
   the code explains the implementation; document context and reasoning.
